# 问题 4 扰动下的重调度与方案比较

## 1 题意与规则

以问题 2(2) 的最优调度为基线（`T1:2.678 s, T2:10.255 s, T3:10.655 s`，`t_last = 10.655 s`），
在 `t = 5 s` 注入扰动：

| 扰动 | 参数 |
|---|---|
| **D1 新告警 T4** | `(θ, R, 50)`，`θ ∈ [0°,360°)`，`R ∈ [30,50] m`，需 2 辆车交会 |
| **D2 单车失效** | 5 辆车等概率，失效车退出服务（不阻碍通行） |
| **D3 通信中断** | `[5, t_rec]`，`t_rec ∈ (5,30]`；中断期间车辆继续当前任务，新指令只能在 `t_rec` 后送达 |

**规则落地**：
- 扰动前**已开始观测**的告警视为完成、不可重调度 → `t = 5` 时 T1 已于 2.678 s 开始 → 完成；
- **已派出但尚未开始观测**的车辆可改派 → T2、T3 仍待观测，V1（等待）、V2（在途）、V4（已指向未观测）可改派；
- 两方案在 `t = 0` 都不预知扰动，重调度只在扰动实际发生后触发；
- 重调度指令的生效时刻 `t_eff = max(5, t_rec)`（通信中断期间指令发不出去）。

## 2 重调度模型

**状态推进**。给定基线事件表与 `t_eff`，把每辆车推进到 `t_eff`：

| 车辆所处阶段 | 可否改派 | 入模状态 `(位置, 可用时刻)` |
|---|---|---|
| 未出发 / 在途 | 可 | (当前位置/路径上按 3 m/s 内插的位置, `t_eff`) |
| 已到站、已指向、等待同伴 | 可 | (测站, `t_eff`) |
| 观测中 / 复位中 | 不可 | (测站, 该任务 `avail`) |

**决策模型**。对"待观测告警集合" `A` 与"当前可用车辆" `V`，决策为

```
每辆可用车 v 最多承担 2 个待观测告警（按可用时刻先后），
每个告警 a 需 2 辆不同车辆与 2 个测站（须在 a 的可观测区域内，交会角 γ ≥ 15°）
min  ( -k ,  t_last )        按字典序：先最大化窗口内成功启动数 k，再最小化最晚开始时刻
s.t. 严格时序：行驶 → 云台转动 → 双车就绪后观测 5 s → 复位 → 再出发
```

**求解**：候选池（1 m 栅格、20° 方位分箱）+ 车辆对枚举（每告警取就绪最早的 4 个车辆对）
+ 告警顺序枚举 + 精确仿真校核；并保留"沿用原分配"作为兜底动作，保证重调度**不会比不改更差**。

**对照策略 S0（保留原方案）**：T1/T2/T3 的原分配一律不动；失效车的任务直接作废
（该告警因不满足"两车交会"而失败）；新告警 T4 由"最早空出的两辆车"补做。

## 3 情景集设计

| 类别 | 规模 | 设计理由 |
|---|---|---|
| 单一-新告警 | 36（θ 每 30°×R∈{30,40,50}） | 观测区域的形状随方位剧变（B1–B5 遮挡），必须全向覆盖；R 取近/中/远三档 |
| 单一-失效 | 5（每辆车一次） | 5 辆车角色不同（2 辆在观测、1 辆在途、1 辆已指向），失效影响差异大 |
| 单一-通信 | 4（`t_rec` = 10/15/20/30） | 唯一作用是推迟指令，取覆盖 (5,30] 的 4 个代表值 |
| 组合 | 48（6θ × 2R × 2 失效车 × 2 `t_rec`） | 分层抽样：方位与距离取端点，失效车取"在途(V2)/已指向(V4)"两类，通信取短/长两端 |

**评价准则**（按题意）：`η = k/N` 优先；`η` 相同再比 `t_last`（窗口 [0,60] s，未开始记 60 s）。
`N` 含新告警（有 T4 时 N=4，否则 N=3）。

### 4.3 典型情景

**① 新告警在东南 `θ=300°, R=50 m`（坐标 (75.0, 6.7)），无失效、无中断**

| | S0 | S1 |
|---|---|---|
| T2 / T3 / T4 开始 | 10.98 / 10.65 / **25.31** | 10.98 / 10.83 / **18.75** |
| T4 的车辆 | V1 + V4（V4 在 (87.5,71.5)，横穿全场） | V1 + V5（V5 在 (49.5,93.5) 已完成 T1 复位） |

S0 把 T4 派给"最早空出"的 V1 与 V4：V4 位于 (87.5, 71.5)，需长途机动到东南角，T4 只能等到 25.3 s；
S1 改用 **V1 + V5**（V5 于 9.2 s 已完成 T1 复位、就在北侧），T3 仍由 V1+V3 承担（仅推迟 0.18 s），
T4 提前到 18.75 s。→ **收益 6.6 s（−26%）**

**② 新告警在正西 `θ=180°, R=30 m` + V2 失效**（`t_eff = 5 s`）

| | S0 | S1 |
|---|---|---|
| η | **0.75**（T2 只剩 V4，无法交会 → 失败） | **1.00**（T2 由 V1+V4 承担） |
| 各告警开始 | T2 失败；T3 10.65；T4 20.01 | T2 20.84；T3 10.65；T4 20.01 |

S0 无法处理"配对被打断"，直接丢掉一个告警；S1 把 T2 重新配对（V1 做完 T3 后与 V4 组合），
代价是 T2 推迟到 20.8 s，但 **η 从 0.75 升到 1.00** —— 按题目"η 优先"的准则，这是净收益。
时间轴见 `figures/Q4_timeline_case.png` 与 `output/q4_caseB_timeline.csv`。

**③ 仅通信中断至 30 s（`t_rec=30`）**：S0 与 S1 完全相同（T2 27.2、T3 19.6、T4 29.1）。
中断只推迟"发令"，不改变资源，重调度没有可动的余地。

## 5 收益来源与失效原因分析

**重调度有收益的两类情景**

1. **新告警引起全局再平衡**（36/36 更优，平均 −5.23 s；全部情景中最大单项改进 8.77 s）：
   新告警的最优执行车辆往往不是"最早空出"的那两辆；需要把某个已完成任务的车"换位"，
   腾出就近的车。贪心的"追加式"分配看不到这种置换收益（该类 36/36 全部更优，平均 −5.23 s）。
2. **失效打断配对**（4/5 提升 η）：一个告警必须两车交会，任一车失效即该告警失败；
   重调度通过"把剩余车重新两两配对 + 允许一车承担两任务"把 `η` 拉回 1。
   代价是 `t_last` 略增（+0.99 s），因为恢复的告警只能排在后面 —— 这正是"η 优先"的体现。

**重调度无收益（或收益被抵消）的情景**

1. **纯通信中断**：信息延迟不是资源约束。`t_rec` 之后车辆状态与 S0 完全一致，且 S0 的追加分配
   本就用"最早可用车"，所以两者重合。**结论：通信中断的影响由 `t_rec` 直接决定
   （t_last ≈ t_rec + 新告警执行时间），重调度无法改善，只能靠"预案/预授权"解决。**
2. **失效但冗余充足**（1/5 持平）：若失效的是 T1 完成后的空闲车（如 V5），所有待观测告警的
   配对不受影响，重调度退化为"沿用原分配"。
3. **组合情景中 t_last 反而变差**（+0.70 s）：为了救回被失效打断的告警，必须让某辆车连续执行
   两个任务，最晚开始时刻被推后；但 `η` 从 0.75 升到 1.00，按字典序仍是改进。

**为什么 S1 从不更差**：模型把"不加改动"作为候选动作之一（安全兜底），
因此 `S1 ≥ S0` 在 (η, t_last) 字典序下恒成立（93/93 无更差）。

## 6 部署建议

1. **失效是最大威胁**：`η` 的损失全部来自"配对被打断"。若允许 6 辆车（或指定 1 辆备份车），
   组合情景下 `η` 可从 0.75 直接到 1.00，且不必牺牲 `t_last`。
2. **新告警应做全局再平衡**，不要"追加式"派车：仅此一项就能把 `t_last` 平均缩短 5.2 s（20%）。
3. **通信中断只能靠预案**：建议在中断前下发"应急规则"（如"若无指令，就近支援最近告警"），
   否则 `t_last` 会被 `t_rec` 直接顶住。
4. **评估窗口的选择会改变结论**：60 s 窗口下 `η` 恒为 1（资源足够），若任务时限收紧到 20 s，
   `η` 的差异立刻显现（0.647 vs 0.715），因此报告 `t_last` 与窗口敏感性同样重要。
